## 1. 产品要解决的问题

把“我希望什么时候做什么”“需要多少钱”“收入和开支是否支撑这些计划”“身体状态如何”“过去发生了什么”放在一个可理解的人生视图里。

产品的核心是一条连接过去、现在和未来的时间轴：过去承载大事记，现在呈现真实记录，未来承载目标与资金预测。它既是一份个人手账，也是帮助长期规划的工具。

## 3. 功能需求

### 3.1 目标规划

目标包含标题、描述、分类、计划日期或时间范围、优先级、状态，以及可选的预算、进度和子目标。

- 日期可以只确定到年份，也可以精确到月份或具体日期；未确定的日期应显示其精度。
- 状态建议包括计划中、进行中、已完成、暂停、取消。
- 支持新增、编辑、归档和删除；删除提供恢复途径。
- 第一版以手动进度和完成状态为主，之后再引入子目标自动汇总。
- 完成目标后可生成关联的大事记，保留原有目标和预算记录。
- 改变日期或预算时，相关资金计算随之更新。

例：2028 年旅行、2030 年购房、某一年转行、提升身体力量。目标可以有预算，也可以完全不涉及资金。

### 3.2 资金预期：这件事可能需要多少钱

每个有资金需求的目标拥有预算明细，如交通、住宿、课程、设备、首付等。支持预算总额、费用发生日期，以及后续的预算和实际花费对照。

建议分两步实现：

1. 第一版由用户填写金额，提供可编辑的预算分类和明细模板。
2. 后续提供辅助估算：结合地点、时间、规模等信息给出区间，并标明来源、估算日期、假设和不确定性；由用户确认后写入目标预算。

“你觉得需要多少钱”的能力保留在产品目标中，但不会把无来源的单一数字当成可靠报价。复杂目标可保留多个估算版本。

目标支出可为一次性，也可分阶段发生。第一版支持一次性预算；分期费用和持续性费用进入后续资金模型。

### 3.3 收入目标：为了实现计划需要赚多少

收入目标需要考虑已有资金的收益和可用时间。输入包括目标预算、当前资金配置、已为目标预留的资金份额、剩余准备时间、日常开支预算、其他固定负担，以及新增储蓄的去向和收益假设。展示目标日期前可用资金、预期收益、资金缺口、每月需要新增的储蓄，以及所需的税后可支配收入。

**当前资金配置**

支持自由添加多笔资金。同一家银行内不同期限或计息规则的存款，可以作为不同资金批次记录，不强行合并。

| 配置项 | 作用 |
| --- | --- |
| 名称与类型 | 自定义名称，如长期储蓄、活期资金、应急金 |
| 金额与余额日期 | 记录本金、已结算收益和预测基准日余额，避免重复计算过去的收益 |
| 年化收益 | 用户填写年化利率或收益假设；未填写时明确按 0% 计算，可随时修改 |
| 起息日、期限、到期日 | 确定剩余计息时间和资金何时可以使用；已存若干年的资金不重新计算完整期限 |
| 计息与结息方式 | 可配置单利/复利、结息周期，以及收益留在原资金中还是转入另一账户 |
| 可支取规则 | 区分随时可取和到期可取；可提前支取但损失收益的情况后续按独立情景计算 |
| 资金归属 | 标记可分配资金、应急储备，以及已分配给各目标的份额 |

你的例子可以保存成两笔独立配置：

| 资金 | 配置 | 对规划的影响 |
| --- | --- | --- |
| 长期储蓄 | 50,000 元，期限 10 年，年化 5% | 按起息日、计息方式和到期规则推算；若设置为到期才可取，提前发生的目标不能直接使用这笔本金 |
| 活期资金 | 200,000 元，年化 1%，可随时支取 | 按实际余额和配置的结息方式计息；支出或转出后，后续收益基数随之减少 |

以上收益率来自用户举例，不对应已选择的真实产品。仅有“10 年、5%”还不足以确定结息方式：若 50,000 元存满 10 年、期间没有追加或支取、忽略税费，单利到期本息为 75,000 元；若按年复利且收益留存，到期本息约为 81,444.73 元。200,000 元在 1% 下保持本金完整满一年，利息为 2,000 元；中途动用资金时重新按余额和时间计算。

**包含收益的收入推算**

> 目标资金缺口 = max（目标预算 − 目标日期前可用于该目标的现有资金本息，0）\
> 每月新增储蓄 = 使新增储蓄及其收益在目标日期前补足缺口所需的月金额\
> 所需月税后收入 = 月日常开支 + 其他固定负担 + 每月新增储蓄

按资金批次分别模拟计息、结息、支取与到期，再汇总可用于目标的金额；新增每月储蓄按实际投入时间计算收益。第一版采用明确的月末新增储蓄假设，去向先支持可追加、可随时支取的账户；不自动把新增储蓄套用到已有的 10 年期 5% 存款。

当所有收益率设置为 0%，且资金均可在目标日期前使用时，回到原来的简单模型：每月新增储蓄 = 资金缺口 ÷ 可准备的月数。

零收益校验例：目标预算 100,000 元，已预留 20,000 元，准备时间为 24 个月，则每月约需新增储蓄 3,333.34 元；若每月日常开支为 4,000 元，且无其他固定负担，则所需月税后收入约为 7,333.34 元。此例为虚构数据，仅演示计算；采用向上取整到分的口径。

必须遵守的计算规则：

- 第一期推算单个目标，并明确“只针对这个目标”；全局收入目标在完整现金流阶段计算。
- 同一笔预留资金只能分配一次；应急储备可设为不可用于目标的金额。
- 日常开支与目标支出分开，关联目标的实际交易不能再次作为未来预算重复扣除。
- 第一版支持多笔资金的年化收益配置、单利/复利和到期限制；收益率由用户填写，预测与实际到账收益分开。通胀、收入增长和更复杂的收益情景后续扩展。
- 区分总资金预计本息、目标日期前可支取的金额和已经分配的金额；锁定本金及未到账、不可支取的收益不能提前抵扣目标费用。提前单独到账且可支取的利息，可以按配置分配给目标。
- 收益已包含在账户本息或收支记录中时，不能再次作为额外收入加入；目标花费、取款或资金转移后更新收益基数。
- 到期后不自动继续沿用原定期利率或假设自动续存。由用户设置到期去向和后续收益率，未设置的后续期间明确按 0% 计算。
- 截止日期已经过去或可准备时间不足时，提示需要补足的金额，避免出现除以零或负的储蓄要求。
- 年份、月份级目标的计算日期需由用户确认，或明确显示采用的日期假设。
- 这里的“收入目标”默认指税后可支配收入；税前工资反推需另行设计，不能直接混用。

### 3.4 当前开支与收入记录

记录金额、日期、分类、收支类型、账户或支付渠道、备注，以及可选的关联目标。

- 手机端支持快速记账，减少必填项，常用分类和渠道可复用。
- 支持编辑、删除、按月汇总、分类统计、实际与预算对比。
- 区分收入、消费、转账和退款；自己的账户间转账不计入消费，退款按关联交易抵扣。
- 转账给他人的用途需可由用户改为消费或其他类型，不能一律忽略。
- 对于信用卡等情况，消费与还款需避免重复统计；复杂债务管理另设后续范围。
- 支持账单文件导入：先预览和映射字段，确认后入账；重复文件不能造成重复记录。
- 支付宝、微信、银行等来源按各自实际格式分别适配，不能用“支持 CSV”替代真实格式验证。

支付宝个人全部消费流水的自动 API 接入目前未核实可用，因此不作为第一版或第 2 期的验收前提。实现路径与证据见技术文档。

### 3.5 健康管理

基础记录建议包括身高、体重、记录日期和备注，显示变化趋势。之后可增加体脂、围度及用户自定义指标。

力量记录以“项目 + 数值 + 单位 + 日期”描述，例如握力、卧推重量、俯卧撑次数，分别展示趋势；肌肉量与力量表现分别记录。指标不足时不生成未经解释的综合身体强度分数。

后续体检报告流程：导入 PDF 或图片 → 提取指标 → 用户校对数值、单位和参考范围 → 保存 → 对照历次变化 → 生成有依据的解释。原始页码或图像位置与提取结果关联，便于检查识别错误。

报告分析作为帮助理解指标和变化的辅助功能。正式做这一阶段前，明确分析服务、数据发送范围、费用和用户授权；分析输出不作为诊断结果。

当前 PWA 通过手动输入和文件导入记录健康数据。直接调用 Apple Health/HealthKit 留作未来原生能力评估，不属于当前 PWA 交付承诺；不能承诺读取所有医院的体检报告。

### 3.6 大事记与统一时间轴

大事记包含标题、发生日期或日期范围、分类、重要程度、事件经过、独立的感想文字和可选附件，支持关联目标。

**文字与感想**

- “事件经过”记录发生了什么，“感想”记录当时的感受、收获、遗憾、反思或其他想写的话，两部分可以分别编辑。
- 感想提供多行文字输入，支持段落、换行和后续补写；可以留空，避免为了完成记录而被迫填写。
- 详情中感想占据清楚的阅读区域，便于回看和继续写。时间轴卡片可显示一小段感想摘要，完整文字在详情中展开。
- 第一版支持基础长文本；更丰富的排版、图片穿插和多次感想追加记录可后续扩展。

**分类颜色与重要程度**

- 分类可由用户添加、重命名和选择颜色，例如家庭、事业、学习、旅行、健康。示例类别及具体配色在原型中确定。
- 同一分类在时间轴、列表和详情中保持同一颜色，提供分类名称或图标与颜色共同识别。
- 重要程度与分类分开设置，暂建议“日常记录 / 重要事件 / 人生里程碑”三级，名称可调整。
- 分类用颜色表达，重要程度用等级标签、节点大小或轮廓表达，让同一类别内不同重要程度也能区分。
- 支持按分类和重要程度筛选；缩放到多年视图时优先展示高等级事件，其余聚合并保留数量，可展开查看。

时间轴的核心交互：

- 浏览：拖动平移、缩放年份或月份、回到今天、跳转指定时间。
- 分层：目标、大事记、资金曲线按需开启，避免所有数据同时占满画面。
- 选中：点击节点后打开详情，阅读事件经过和感想；桌面用侧栏，手机用独立页面或底部面板。
- 密集节点：按时间和类别聚合，展开后查看各条记录。
- 日期精度：年份或月份级目标显示区间，避免看起来像已确定的某一天。
- 修改日期：与浏览动作区分。后续可在明确编辑模式下拖动节点，预览影响后保存，并支持撤销。

Windows 可使用宽幅时间轴与详情侧栏；iPhone 可采用适合触摸的时间轴浏览和紧凑日历/列表。两端使用同一时间模型，不要求把电脑画面缩小到手机上。

### 3.7 时间轴上的资金曲线

在同一可见时间范围内，按需展示收入、日常支出、目标支出、储蓄收益和资金余额。前几项是某个周期内的流量，余额是累计量；默认分成对齐的小图，清楚标注单位，避免把不同含义的数值混在一条轴上。余额图层区分总资金预计本息和可用于支出的余额。

- 已发生数据用实际记录，未来部分用预测，今天的位置清楚可见。
- 选中某个月或某一年，同时看到该时点的目标、大事记和资金状况。
- 目标支出发生的时点可见，预计余额不足的区间有解释。
- 修改收入、开支、资金配置、收益率、到期日、目标日期或预算后，生成新的预测。
- 标出资金到期节点，解释某笔长期资金何时进入可用余额；已计提收益与实际可支取收益分别展示。
- 情景比较先不覆盖已保存方案，用户可以选择采用或取消。
- 未记录的历史月份标为“无数据”；预测在缺少输入时说明缺少什么，避免默认成真实的零。

后续全局模型：

> 期末可用余额 = 期初可用余额 + 本期预计净收入 + 本期可支取到账收益 + 锁定/预留资金池净转入 − 本期日常开支 − 本期目标支出 − 其他已建模负担

本式中的净收入不重复包含已单独列出的储蓄收益；到期资金从锁定池转入可用池属于资金转移，不是新增收入。各账户先根据计息与可支取规则更新，再汇总；留存在锁定账户中的收益只影响该账户预计本息。

根据所有目标的费用日期逐期检查余额，计算所需的收入水平。它需要覆盖较早的目标截止日期，不能简单把全部预算除以最长时间。

## 4. 页面与信息架构建议

| 页面 | 主要作用 |
| --- | --- |
| 今日/首页 | 看近期目标、记录入口和当下摘要，以用户最常用任务为主 |
| 人生时间轴 | 浏览过去与未来，通过颜色和等级识别大事记、阅读感想，关联目标和可选资金图层 |
| 目标 | 管理目标、预算与执行状态，进入目标详情 |
| 资金 | 配置当前存款及年化收益，记录收支、查看预算与实际、进行资金推算 |
| 健康 | 记录身体数据、查看趋势和后续报告 |
| 设置 | 账户、同步、备份、导出与外部连接 |

建议手机底部导航控制在少量主要入口；“快速记录”可承载开支、体重和大事记。具体导航结构在原型中比较后决定。

## 5. UI 与交互作为独立交付

### 视觉方向

温暖、安静、有生活感，同时能清晰阅读中文和数字。可探索奶油白或纸张色、少量低饱和暖色、自然插画和克制的手账元素；实际配色、字体和装饰比例由第 0 期设计方案确定。

数字、日期和操作文字保持易读。手写字体、纸张纹理、阴影与动效主要用于营造氛围，不影响信息识别和操作效率。

### 设计工作与交付物

1. 视觉参考与 2–3 个方向草案，确定喜欢的气质。
2. 桌面与手机的关键任务流程，包括目标创建、时间轴查看、快速记录。
3. 首页、时间轴、目标详情、大事记详情和资金配置的 Windows/iPhone 高保真设计与可点击原型。
4. 色彩、字号、间距、圆角、图标、卡片和动效的统一规范。
5. 每期新增页面和完整状态设计，并用运行中的截图核对设计。

第 0 期建议将主要精力投入视觉与交互；后续每期保留专门的打磨和审阅环节。不会以“功能能点通”替代 UI 验收。

### 设计验收条件

- 用户审阅后认可整体气质、信息层级和关键操作。
- 桌面适合键盘鼠标，手机适合单手触摸；常用操作不需要绕行。
- 长中文标题、空数据、大量节点、金额较大时布局仍清楚。
- 大事记的分类与重要程度能分别识别；感想长文易读，筛选和多年聚合不会丢失事件入口。
- 资金配置能清楚显示本金、收益、到期日和可用金额，不把长期锁定资金显示成随时可花的钱。
- 必要流程包含加载、无数据、失败、离线、待同步和同步冲突状态。
- 保存到本机与已同步到云端的提示真实，失败后有恢复路径。
- 触摸区域、对比度、系统字体放大、键盘焦点和减少动态效果经过检查。
- 时间轴滑动和动画在约定设备上实测，性能结果与实际测试平台一起报告。

## 7. 数据与可信度要求

- 两端记录共享同一个人账户；云端数据按账户隔离。
- 金额、日期、资金归属和估算假设可以回溯；真实记录与预测分开。
- 提供可读的数据导出和备份恢复路径；云同步本身不能替代备份。
- 发生同步冲突时保留两个版本，不能静默覆盖财务或健康数据。
- 体检报告、账单、数据库和服务密钥不进入 GitHub；示例数据使用虚构内容。
- 健康报告和第三方分析在相关阶段明确存储位置、发送范围和删除方式。
