# 从愿望预算反推月薪

日期：2026-10-12 · 版本：v0.0.20

本版落实用户确认的口径：**暂不计现有存款，全部靠未来工资实现愿望。** 输入是愿望费用、付款日期和日常开销，输出是实现全部已填预算愿望所需的最低固定月薪。现有资产、本金收益、基金市值和定期到期资金都不抵扣。第 28、29 份文档保留为版本记录，涉及已有资金抵扣、自填收入与起点余额的描述以本文为准。

## 怎么使用

1. 在“心愿与目标”中填好每个愿望的一次性费用、每月持续费用与起止时间。已完成愿望不再计费；未填预算的愿望先提示补齐。
2. 打开“资金安排 → 资金安排”。最上方的“实现这些愿望，月薪要多少？”直接显示税前月薪目标和对应税后到账额，不需要填写希望挣多少。
3. 展开“规划假设与收入换算”，核对每月日常开销。初次参考最近一个已结束月份的支出；没有参考记录时先算愿望费用的月薪下限，明确标注尚未包含生活费。补填后立即重算。
4. 活期复利默认 0.8% 年化，只施加于未来工资扣除开销后的结余。修改年化也会重算；本金为零时不会凭空产生利息。
5. 税前换算可填写个人社保、公积金及专项附加扣除。算法与来源沿用 [第 29 份说明](29-收入测算与曲线明细.md#税前与税后)，个人金额默认 0，不猜测城市缴费比例。
6. “这份月薪怎么算出来？”展示为愿望每月需留的金额、日常开销和税后工资下限，并列出愿望费用与最约束月薪的付款日期。点“保存规划假设”后才记住设置；预览不会改动真实资产和账单。

如果持续月费已经包含在日常开销中，勾选对应愿望的标记，避免同一笔费用算两遍。近期要付款的愿望可能需要更高工资；总预算除以总月份不能保证早期愿望按时付钱。

## 反推规则

从今天起建立独立的工资规划，初始余额为 0。整月工资、日常开销及持续月费从**下个月**开始，假设工资每月月初到账，再支付当月费用。未完成的一次性愿望按具体日期付款，本月尚未付款的愿望也保留。

每次付款后的余额可以表示为 `A + B × 税后月薪`。`A` 累计费用，`B` 累计已发工资及其结余的复利影响。按每两个日期间实际天数 / 365 对余额使用有效年化复利。在所有付款时点取保证余额不低于 0 的最大月薪下限，向上取整到分；再换算所需税前工资。

测算截止日是最后一个未来预算愿望的日期，独立于时间轴当前浏览范围。只调整缩放、拖动或筛选不会改变月薪。若本月费用早于下次工资，在初始余额为 0 的条件下无法由未来工资支付，显示“下次工资前需先筹款”及缺口，不编出一个能解决过去付款的月薪。

**虚构例子：**从 2026-10-12 开始，旅行在 2027-10-31 花费 60,000 元，未来有 12 次月初工资，每月生活费 3,000 元。按 0% 年化，税后至少需要 **8,000 元 / 月**：愿望 5,000 + 日常 3,000。按 0.8% 年化，税后下限是 **7,978.50 元 / 月**，未来工资结余的复利贡献使它略低。即使另有 120 万元资产，本次反推也保持这个结果。这个例子不是用户的个人收入目标。

## 同一条时间轴

完整曲线保留在“人生时间轴 → 资金轨迹”。资金页只提供跳转和月薪反推，时间轴上的“调整月薪反推”可返回设置。两页共用结果：未来收入线使用**算出来的月薪**，旧版自填收入不会替代结果。

“月收入与支出”显示工资与结余利息、日常与愿望费用的实线；“工资结余”显示未来工资规划的剩余金额。今天起点标为“工资规划起点”，余额为 0，不能把它误认为真实账户余额。悬停、点选、手机轻点与键盘月份明细继续可用。历史月结仍展示实际记录；未记录历史余额不补造。

税前 / 税后切换只决定收入线的显示口径，工资结余始终使用税后现金。浏览到最后一个预算之后继续沿用算出的工资与日常开销，只作延续试算，不增加已经结束的愿望费用。

## 数据与验证

`financialPlan` 增加可选 `fundingSource`。当前应用载入后使用 `salary-only`，不自动写回旧手账；保存假设时才记录选择。原资产和月结数据保留，旧自填收入字段留在 JSON 中，但不驱动本版工资反推或曲线。无账号或数据格式升级。

`check:salary` 核对预算反推、早期付款约束、现有本金及到期资金排除、旧自填收入忽略、混合一次性与持续费用、重复费用标记、仅工资结余复利、实际余额不负、浏览范围不改变目标，以及试算不修改输入。旧资产模式兼容测试继续单独通过。

浏览器在隔离端口中使用虚构数据检查：修改预算与开销会重算、首屏月薪与依据、无重复时间轴、无自填工资入口、保存重载、真实资产与月结不变、未填开销的下限及聚焦按钮、当月付款缺口、悬停费用与日期、零起点标注、税前切换不改变结余。320 / 390 / 768 / 1440 宽度无页面横向溢出；触控模拟可点选明细。Windows WebView2 独立测试配置也验证主流程。手机验证为尺寸与触控模拟，未声称完成 iPhone 实机验证。
